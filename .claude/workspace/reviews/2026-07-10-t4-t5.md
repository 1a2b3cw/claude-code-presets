### 变更完整性

1. `workbench/poc/server.mjs:90` 的 `chooseFocusTask()` 在所有 Phase 5 任务都 `done` 时 fallback 到 `tasks.at(-1)`，导致 `workbench/poc/server.mjs:171` 的 Next Best Action 继续围绕已完成任务生成。
   - 严重度：major
   - 影响：T5.3 完成后，PoC Today/Task Focus 仍显示 `T5.3` 为 focus，并建议继续 T5.3；这违背 Workbench “下一步建议可信”的核心目标。
   - 建议修复：没有非 done 任务时返回 `null`，并优先使用最新 event 的 `next` 字段；`--check` 增加断言，防止 all-done 队列继续返回 done task。
   - 状态：已修复。`chooseFocusTask()` 不再 fallback 到最后一个已完成任务；`--check` 增加 all-done 断言。

### 跨文件一致性

1. `create-claude-team/scripts/tarball-smoke.js:27` 在 Windows 上通过 `shell: true` 拼接命令字符串，但后续参数包含临时目录和 tarball 路径（如 `tarballPath`、`cliPath`）。
   - 严重度：minor
   - 影响：如果 Windows 用户名或临时目录包含空格，`npm install <tarball>` 或 `node <cliPath>` 可能被 shell 拆参而失败。CI 当前路径通常无空格，所以现有 gate 不一定覆盖。
   - 建议修复：Windows 下不要把命令和参数 join 成字符串；改为解析 `npm.cmd` / `node.exe` 后用 `spawnSync(command, args, ...)` 传数组，或对参数做可靠 quoting。
   - 状态：已修复。Windows 下通过 `process.execPath` 调用 npm CLI 和 node，路径参数保持数组传递；已用带空格 TEMP 复验。
