# Dogfood 记录

> 目标：连续 30 天用真实项目验证 Workbench、standup、events、review 和 release 是否真的减少决策成本。

## 记录原则

- 每天只记录能改进流程的事实，不写流水账。
- 优先记录 Workbench 或 standup 是否帮你决定下一步。
- 如果建议不可信，记录原因和缺失 artifact。
- 每周复盘一次，把重复问题转成任务、规则建议或 Workbench 改进。

## 每日记录字段

| 字段 | 说明 |
|------|------|
| 日期 | YYYY-MM-DD |
| 项目 | 仓库或产品名 |
| 今日焦点 | 当天主要任务或决策 |
| 使用入口 | Workbench / standup / dev / review / ship |
| 是否靠 Workbench/standup 决定下一步 | yes / no / partially |
| 下一步是否可信 | yes / no / uncertain |
| 缺失 artifact | tasks / events / review / release / metrics / none |
| 问题 | 误导、缺失、重复、噪音或阻塞 |
| 改进动作 | 要补的任务、规则、测试或文档 |

## 每周复盘字段

| 字段 | 说明 |
|------|------|
| 周期 | YYYY-MM-DD 至 YYYY-MM-DD |
| 有效建议 | 哪些 Next Best Action 真的减少了决策成本 |
| 误导建议 | 哪些建议不可信，原因是什么 |
| 缺失数据 | 哪些 artifact 最常缺失 |
| 重复问题 | 一周内重复出现的失败、打回或阻塞 |
| 下周改进 | 下一周最值得修的 Workbench/standup/流程问题 |
