# 移动端性能参考

## 关注面

| 场景 | 风险 | 优先手段 |
|------|------|----------|
| 冷启动 | 首屏慢、白屏 | 减少启动同步工作，延迟非关键 SDK |
| 长列表 | 掉帧、内存高 | FlatList/FlashList、稳定 item、高效图片 |
| 图片 | OOM、加载慢 | 缩略图、压缩、缓存、固定尺寸 |
| 动画 | JS 线程阻塞 | Reanimated、原生驱动、减少 layout thrash |
| 表单 | 键盘卡顿 | 控制渲染范围，避免全页状态更新 |
| 网络 | 电量和流量 | query cache、退避重试、取消无用请求 |

## 测量顺序
1. 复现卡顿或慢启动。
2. 确认设备、构建类型、系统版本。
3. 用 profiler 或原生日志定位 JS、layout、图片、网络还是原生瓶颈。
4. 只优化热点。
5. 在同一设备上复测。

## 常见优化
- 大列表 item 使用纯展示组件，避免订阅全局 store。
- `renderItem`、`keyExtractor`、header/footer 组件保持稳定引用。
- 搜索、筛选、格式化等昂贵计算用 memo 或移到 service 层。
- 图片先确定尺寸，再加载资源。
- 非关键 SDK 初始化延后到首屏后。
- Analytics 事件批量发送，失败重试有上限。

## 反模式
- 为了“感觉更快”先加动画，实际没有减少等待。
- 没有测量就到处加 `memo`。
- 把服务端列表复制到 Zustand。
- 只在开发模式评估性能。
