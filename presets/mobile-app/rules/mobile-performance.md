# 移动端性能规则（必须遵守）

## 必须做
- 性能问题先测量，再优化。
- 首屏、列表滚动、图片加载、动画、键盘交互和冷启动都要在目标设备上验证。
- 长列表使用虚拟化列表，复杂列表优先 FlashList。
- 图片上传前压缩，列表图使用缩略图，避免直接加载原图。
- 动画优先使用 Reanimated 或原生驱动能力，避免 JS 线程高频动画。
- 生产构建或 development build 上确认性能，不只看 Expo Go。

## 禁止做
- 不用 `ScrollView` 渲染可能增长的数据列表。
- 不在 render 阶段做同步大计算、JSON 解析或格式化大数组。
- 不把大型对象放进全局 store 导致无关页面重渲染。
- 不用无界重试或轮询拖垮电量和网络。

## 性能预算
- 列表滚动不能有持续卡顿。
- 关键交互应有即时反馈。
- 启动页到首个可操作界面要有明确 loading/skeleton。
- 包体积增加需要说明原因，重型 SDK 必须按需引入。
